① まず全体像：4つの層

このシミュレーターは、実は「4枚のレイヤーを重ねた絵」です。それぞれ別の仕事をしています。

🌊 波の形きれいな波を11本、足し算して海面の高さを作る
🗺 泡マップ波頭で生まれた泡を「記憶」して、後ろで薄れさせる
🫧 泡の粒小さな泡が生まれ、水に乗って動き、弾ける
💦 飛沫泡が弾けた場所から、水しぶきが放物線で飛ぶ
スライダー→数値（パラメータ）→GPUが計算→画面に表示
全部ブラウザの中で、リアルタイムに動いています。サーバーは使っていません。

② 波は「足し算」でできている

1本の波を式にすると

高さ ＝ A · sin( k·x − ω·t + φ )
記号意味スライダーでは
A振幅（波の高さの半分）風波の高さ
λ（ラムダ）波長（山から山まで）風波の波長
k = 2π / λ波数（1mに波が何周期入るか）—
ω, t時間の進み方と現在時刻波の速さ・スロー倍率
φ（ファイ）位相（波のスタート位置のずれ）🎲 乱数を変える

波の速さは、波長で決まる

深い海の波は、長い波ほど速く進みます。これは水の物理（分散関係）から出てきます。

ω² ＝ g · k　→　速さ c ＝ √( g / k )　（g ＝ 9.8 m/s²）
この「波長ごとに速さが違う」性質を分散と呼びます。光が虹に分かれるのと同じ言葉です。プログラムでは sqrt(9.8/k) の1行で入っています。

重ね合わせの原理

複数の波が同じ場所に来ると、高さは単純に足し算になります。これが「重ね合わせの原理」です。このシミュレーターは、風波を最大8本、うねりを3本、合計11本を足しています。波ごとに波長を 0.72倍 ずつ小さくして、大きなうねりの上に細かいさざ波が乗るようにしています。

③ 水は円を描く、だから波頭が尖る

実際の水の粒は、波が通るとき上下だけでなく前後にも動いて、円を描きます。この動きをそのまま式にしたのが「Gerstner（ガーストナー）波」です。波の山は尖り、谷はなだらかになって、海らしい形になります。

x ＝ x₀ ＋ Σ Qᵢ Aᵢ Dᵢ cos(fᵢ)
y ＝ Σ Aᵢ sin(fᵢ)
fᵢ ＝ kᵢ ( Dᵢ·x₀ − cᵢ t ) ＋ φᵢ
記号意味
x₀水の粒の「もともとの位置」（動く前）
D波の進む向き（風向で決まる）
Q尖り具合（スライダー「鋭さ」）
Σ11本ぶんを全部足す、という記号
Qが大きすぎる（Q·k·A が1を超える）と、波が自分自身に絡まって、水面が裏返ります。このシミュレーターでは、その「ぎりぎり」を白波が出る目安にも使っています。

前が急な波にする

岸に近づく波は、前が急で後ろがなだらかです。位相を少しゆがめるだけで作れます。

f′ ＝ f − a · sin(f)
泡が水に乗って動くのは、この「x₀（水の粒の元の位置）」を基準に計算しているからです。泡をx₀に固定すると、波が通るたび、水と一緒に自然に動きます。

④ 一様じゃ変。ランダムが「本物らしさ」

実際の海は、向きも位相もバラバラな波の重なりです。だから規則正しい足し算では、人工的に見えます。ここには4つの工夫があります。

位相をランダムに波ごとのスタート位置をずらす
向きを散らす風向を中心に±でばらつかせる
うねり別方向から来る長い波を足す
ムラ場所ごとに高さを増減して、強弱をつける
乱数は「種（シード）」から作ります。同じ種なら同じ海が再現できるので、「🎲 乱数を変える」は種を変えているだけです。波を周波数ごとの正弦波に分解する考え方をフーリエ解析と呼び、本格的な海のCGは、この原理（FFT）で作られています。

⑤ 白波：いつ泡は生まれる？

泡のでき方の目安

波頭で水が寄せ集められ、混み合うほど、波は砕けやすくなります。その混み具合を、式で測ります。

J ＝ Σ Qᵢ · kᵢ · Aᵢ · sin(fᵢ)

Jが大きいほど「ここは砕けそう」です。これを0〜1の泡の量に直すのが、smoothstep という「なめらかなスイッチ」です。

泡マップ：泡に「記憶」を持たせる

白波は、波頭が過ぎたあとも泡が残って、ゆっくり消えます。これを再現するために、泡の量を絵として保存する別の画面（泡マップ）を用意して、毎フレームこう更新しています。

新しい値 ＝ max( 古い値 − 時間 / 持続秒数 , 今の泡 )

古い値を少し減らし、波頭の新しい泡と比べて、大きいほうを残すだけです。これで、波頭の後ろに、薄れていく泡の尾ができます。

泡のつぶつぶ感：ノイズ

泡の細かい模様は、ノイズという「それっぽいランダムな濃淡」で作ります。大きさの違うノイズを重ねるfBmを使い、周波数を2倍、強さを半分ずつにしていきます。

fBm ＝ n(p) ＋ ½ n(2p) ＋ ¼ n(4p) ＋ …

網目状の泡は、ノイズを 1 − |2n − 1| と加工して、線のように浮かせています。凹凸は、ノイズの傾き（勾配）から法線（面の向き）を作り、光を当てて陰影にしています。

⑥ 泡の粒と飛沫：ボールを投げる物理

飛沫は、投げたボールと同じ

飛沫の粒は、波頭から飛び出したあと、重力で落ちます。高校物理の放物運動です。

y ＝ y₀ ＋ v · t − ½ · g · t²

横方向には、空気抵抗で少しずつ失速する式を使っています。

進んだ距離 ＝ v · ( 1 − e−0.4 t ) / 0.4

10万粒でも軽い、「記録しない」計算

普通は、粒ごとに「今どこにいる？」を毎フレーム更新します。でも、数万個になるとスマホには重すぎます。そこで、粒の位置を保存せず、時刻 t から毎回、式で直接求める方法にしています。「生まれた時刻」と「今」の差（年齢）さえ分かれば、位置は式で出せるからです。

この方式をステートレス（状態を持たない）な計算と呼び、GPUがとても得意です。粒ごとの乱数は fract(sin(…)×43758.5) という、少し不思議な「ハッシュ関数」で作っています。

泡の一生

🫧 生まれる→膨らむ→水に乗って移動→縮んで弾ける→💦 飛沫が飛ぶ

弾ける時刻と場所から、そのまま飛沫を計算するので、泡と飛沫が自然につながります。

⑦ プログラムの設計：3つの言語が分業

担当言語やっていること
見た目のパネルHTML / CSSスライダーとボタンを置く
司令塔JavaScript（three.js）数値の管理、毎フレームの指示
計算と描画の本体GLSL（シェーダー）GPUで波・泡・飛沫を一気に計算

データの流れ

スライダー→オブジェクト P→U() が uniform に反映→シェーダーが読む
const P = { height:1.2, steep:0.7, wind:30, ... };   // 全パラメータ
slider.addEventListener('input', () => { P[k] = +slider.value; U(); });

シェーダーの用語

用語ひとこと説明
頂点シェーダーメッシュ（9万点の網）の各点を、波の高さへ動かす
フラグメントシェーダー画面の1ピクセルごとの色を決める
uniform全員で共通の値（波の高さ、時刻など）
attribute粒ごとに違う値（乱数の種）
varying頂点からピクセルへ渡す値

毎フレームやっていること（1秒に約60回）

function loop(now){
  T += dt * スロー倍率 * 波の速さ;   // 1. 時間を進める
  foamStep();                        // 2. 泡マップを更新
  cam.position.set(...);             // 3. カメラを置く
  R.render(sc, cam);                 // 4. 描画
  requestAnimationFrame(loop);       // 5. 次のフレームへ
}
JavaScriptがやるのは「時間を進めて、描いてね」と指示するだけです。重い計算は、全部GPUが並列でやっています。

3つの設計の工夫

① メッシュ300×300の網（約9万点）を波の高さで動かす
② 泡マップ画面とは別の絵に書き込み、前の絵と交互に使う（ピンポン）
③ 粒をGPUで位置を保存せず、時刻から式で直接求める

⑧ できないことと、次の一歩

波頭の巻き込みが作れない理由

このシミュレーターの海面は、「場所（x, z）を決めると、高さ y が1つ決まる」形です。だから、波頭が前に張り出して、下に空洞ができる巻き波は、原理的に表現できません。

本物に近づく方法

方法特徴
FFT海洋（Tessendorf）大海原の見た目を軽く再現。映画やゲームの定番
SPH（粒子法）水を粒の集まりとして計算。砕波や飛沫が作れるが重い
格子法（VOF）水と空気の境目を追う。研究や映像制作向け

これらは、水の動きを支配するナビエ・ストークス方程式を解いています。今回の波は、その「見た目を真似る近道」です。
